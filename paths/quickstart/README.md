# Quickstart

The required onboarding path takes a product from idea to working application.
It is intentionally technology-neutral: learners choose an idea first, define
what success means, and only then select tools and build.

## Tasks

| Order | Task | Outcome |
| --- | --- | --- |
| 1 | [Decide what to build](01-decide-what-to-build.md) | A focused product brief |
| 2 | [Define the specification](02-define-the-spec.md) | A build-ready specification |
| 3 | [Build the application](03-build-the-app.md) | A tested, runnable app |

Complete the tasks in order. Each task should have its own GitHub issue.

## Finish line

Quickstart is complete when all three task issues are closed and another person
can run the application by following its README.
